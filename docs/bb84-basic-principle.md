# BB84 基本物理原理

BB84 是一種量子金鑰分配協定，目的不是直接傳送訊息，而是讓 Alice 和 Bob 產生一組共同密鑰。

它的安全性主要來自兩個量子力學特性：

1. 量子態不能被任意測量而不造成影響。
2. 測量會改變量子態。

## 基底與 bit

Alice 會隨機產生 bit，並隨機選擇基底來傳送光子。

| 基底 | bit 0 | bit 1 |
|---|---|---|
| Z / + 基底 | 垂直偏振 | 水平偏振 |
| X / × 基底 | 45 度偏振 | 135 度偏振 |

Bob 收到光子後，也會隨機選擇基底來測量。

- 如果 Alice 和 Bob 使用相同基底，Bob 通常能得到正確 bit。
- 如果 Alice 和 Bob 使用不同基底，Bob 的結果會接近隨機。

## Sifting

傳輸完成後，Alice 和 Bob 會公開比較「使用了哪些基底」，但不公開 bit 內容。

只有雙方基底相同的位置會被保留下來，形成 sifted key。

## QBER

QBER 是 Quantum Bit Error Rate，表示 Alice 和 Bob 在相同基底下結果不一致的比例。實際協定只公開隨機選取的測試位元來估計錯誤率，其餘位元不會為了計算 QBER 全部公開。

```text
估計 QBER = 公開測試位元中的錯誤數 / 公開測試位元數
```

如果 QBER 很低，代表通道大致正常。

如果 QBER 很高，可能代表：

- 自然雜訊。
- 設備誤差。
- 光子翻轉。
- Eve 竊聽。

## Eve 攔截重送攻擊

最基本的 Eve 攻擊是 intercept-resend：

1. Eve 攔截 Alice 傳出的光子。
2. Eve 隨機選基底測量。
3. Eve 根據自己的測量結果重新送一個光子給 Bob。

問題是 Eve 不知道 Alice 原本使用哪個基底。當 Eve 選錯基底時，就會改變光子的狀態，導致 Bob 的測量結果出現額外錯誤。

因此，Eve 的存在通常會讓 QBER 上升。

## 為什麼還需要 AI

只看 QBER 可以判斷通道是否異常，但不一定能分清楚「自然雜訊」和「Eve 竊聽」。

資料交接只使用 Alice 和 Bob 可以觀測或公開比對的統計，例如：

- 總錯誤率。
- Z 基底錯誤率。
- X 基底錯誤率。
- 光子點擊率與測試位元數。
- 後續階段的時間窗變化及偵測器統計。

模擬器設定的雜訊強度與 Eve 是否存在是驗證用真值，不是 AI 輸入。現有第一批資料主要用來跑通訓練流程；當自然雜訊和 Eve 造成相同觀測時，AI 也不能只憑這些數值確定成因。資料欄位見 [CSV 格式規格](csv-format.md)。
